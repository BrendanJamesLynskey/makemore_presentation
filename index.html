Part 1

The Problem & the Data

From a list of names to a model that invents new ones

names.txt — ~32K Names

# One name per line
words = open('names.txt', 'r').read().splitlines()

len(words)        # 32033
words[:8]
# ['emma', 'olivia', 'ava', 'isabella',
#  'sophia', 'charlotte', 'mia', 'amelia']

min(len(w) for w in words)   # 2
max(len(w) for w in words)   # 15

What: The 32,033 most common US baby names from 2018 (sourced from ssa.gov) — all lowercase, one per line.

The goal: learn the statistical structure of these names so we can make more of them — plausible new names that were never in the list.

names.txt (first lines)

A Character-Level Vocabulary

# All the lowercase letters used in the names
chars = sorted(list(set(''.join(words))))   # ['a', 'b', ..., 'z']

# Map characters to integers, reserving 0 for the special token '.'
stoi = {s:i+1 for i,s in enumerate(chars)}   # a→1, b→2, ..., z→26
stoi['.'] = 0                                  # start / end token
itos = {i:s for s,i in stoi.items()}          # integer → character

vocab_size = len(itos)   # 27

The special . token (index 0) does double duty: it marks both the start and the end of a word. Wrapping each name as .emma. lets a single model learn which characters begin a name, which follow each other, and which end it.

Framing the Task

P( name ) = ∏t P( ct | context )

Autoregressive modelling: the probability of a whole name is the product of the probability of each character given what came before it. Predict one character at a time, feed it back in, and repeat.

The simplest possible context is just the single previous character — that is the bigram model of Part 2. Later parts widen the context (an MLP over several previous characters, then a WaveNet-style hierarchy).

# Wrap every word with the start/end token, then walk character pairs
for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1, ix2 = stoi[ch1], stoi[ch2]   # (previous char, next char)

Part 2

The Bigram Model

Just count the pairs — no gradient descent required

Counting Bigrams into a 27×27 Matrix

import torch

# N[i, j] = how many times character j follows character i
N = torch.zeros((27, 27), dtype=torch.int32)

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1, ix2 = stoi[ch1], stoi[ch2]
        N[ix1, ix2] += 1            # tally this pair

That is the entire "training". One pass over the data, incrementing counts. N[0] (row for .) counts which letters start names; the column for . counts which letters end them.

The matrix is small enough to look at directly — hover the heatmap below to read off real co-occurrence counts.

The Count Matrix N (hover to inspect)

Rows = previous character · Columns = next character · brighter = more frequent

The bright cell at row ., column a reflects how many names start with "a"; the n→. cell reflects how many end in "n". (Counts here are illustrative, scaled to the real distribution.)

Normalising Rows into Probabilities

# Convert counts to a probability distribution per row.
# Model smoothing: add 1 to every count so nothing is exactly zero.
P = (N + 1).float()
P /= P.sum(1, keepdim=True)      # each row now sums to 1.0

Row-normalisation: dividing each row by its total turns counts into P(next | previous). The keepdim=True matters — it keeps the divisor shaped (27, 1) so it broadcasts correctly across columns.

Smoothing (+1): adding one to every count guarantees no probability is exactly zero. Without it, an unseen bigram would give the model infinite loss when it later appears. More smoothing → a flatter, more uniform model.

Sampling & Evaluating (NLL)

# Sample a name, one character at a time
g = torch.Generator().manual_seed(2147483647)
ix = 0                       # start at '.'
out = []
while True:
    p = P[ix]               # row = dist. over next char
    ix = torch.multinomial(
        p, num_samples=1,
        replacement=True, generator=g).item()
    if ix == 0: break       # hit the end token '.'
    out.append(itos[ix])
print(''.join(out))         # e.g. 'mor', 'axx', 'minaymoryles'
# Loss = average negative log-likelihood
log_likelihood = 0.0
n = 0
for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        prob = P[stoi[ch1], stoi[ch2]]
        log_likelihood += torch.log(prob)
        n += 1
nll = -log_likelihood / n
print(f'{nll=}')   # ~2.45

torch.multinomial draws a character index in proportion to the row's probabilities. Negative log-likelihood is the loss: the average -log P assigned to the true next characters. Lower is better; a uniform model would score log(27) ≈ 3.30, so ~2.45 is a real improvement from just counting.

Part 3

The Bigram as a Neural Net

The same model, now trained by gradient descent

One-Hot Inputs × a 27×27 Weight Matrix

import torch.nn.functional as F

# Build the training set of (input char, target char) pairs
xs, ys = [], []
for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        xs.append(stoi[ch1]); ys.append(stoi[ch2])
xs, ys = torch.tensor(xs), torch.tensor(ys)

# A single 27x27 weight matrix — the only parameters
g = torch.Generator().manual_seed(2147483647)
W = torch.randn((27, 27), generator=g, requires_grad=True)

Each input character is turned into a one-hot vector of length 27. Multiplying a one-hot by W just selects one row of W — so W plays exactly the role the count matrix did, but now its entries are learnable.

Logits → Softmax → Cross-Entropy

xenc = F.one_hot(xs, num_classes=27).float()   # (N, 27)
logits = xenc @ W                # (N, 27)  -- log-counts
counts = logits.exp()            # exponentiate → positive "counts"
probs  = counts / counts.sum(1, keepdim=True)   # softmax → P(next)

# Negative log-likelihood of the correct next characters (+ regularisation)
loss = -probs[torch.arange(len(xs)), ys].log().mean() + 0.01*(W**2).mean()

This is the "softmax" written out by hand: exp turns logits into positive numbers (interpretable as counts), then normalising gives probabilities. The loss is the same negative log-likelihood as Part 2.

Equivalence: minimising this cross-entropy is the smoothed counting model. The 0.01*(W**2) regularisation term acts just like the +1 smoothing — pulling W toward zero gives a more uniform, smoother distribution.

Training W by Gradient Descent

for k in range(100):
    # forward pass
    xenc = F.one_hot(xs, num_classes=27).float()
    logits = xenc @ W
    counts = logits.exp()
    probs = counts / counts.sum(1, keepdim=True)
    loss = -probs[torch.arange(len(xs)), ys].log().mean() + 0.01*(W**2).mean()

    # backward pass
    W.grad = None
    loss.backward()             # autograd fills W.grad

    # nudge the weights downhill
    W.data += -50 * W.grad      # large LR because the problem is convex

The punchline: gradient descent on this 729-parameter net converges to essentially the same loss (~2.45) as direct counting. The neural-net framing buys nothing here — but it is the template that does scale, because we can now swap in richer architectures and let autograd do the work. Everything that follows is this same loop with a bigger model.

Part 4

The MLP — Bengio 2003

A wider context and a learned embedding of characters

Block Size & the Embedding Table C

block_size = 3        # how many previous chars to condition on

# Build (context, next-char) examples, sliding the window per word
X, Y = [], []
for w in words:
    context = [0] * block_size           # start: '...'
    for ch in w + '.':
        ix = stoi[ch]
        X.append(context); Y.append(ix)
        context = context[1:] + [ix]     # crop and append
X, Y = torch.tensor(X), torch.tensor(Y)

# Each of 27 chars → a learned 10-dim vector
C = torch.randn((27, 10))               # the embedding table

Instead of one previous character we now use block_size of them. Each character index looks up a row of C — a dense embedding — so similar characters can come to share similar vectors. This is the model from Bengio et al. (2003), the paper that launched neural language models.

Hidden tanh Layer → Output Logits

# Parameters
C  = torch.randn((27, 10))
W1 = torch.randn((10 * block_size, 200)); b1 = torch.randn(200)
W2 = torch.randn((200, 27));              b2 = torch.randn(27)
parameters = [C, W1, b1, W2, b2]

# Forward pass
emb = C[X]                       # (N, block_size, 10)
h = torch.tanh(emb.view(-1, 30) @ W1 + b1)   # (N, 200) hidden layer
logits = h @ W2 + b2             # (N, 27)
loss = F.cross_entropy(logits, Y)            # softmax + NLL in one call

Three stages: concatenate the block_size embeddings into one flat vector, pass through a hidden layer with a tanh non-linearity, then a final linear layer to 27 logits. F.cross_entropy fuses softmax + NLL — numerically safer and faster than doing it by hand.

Minibatching, LR Finding & Splits

# Minibatch: don't use all 200K+ rows each step
for i in range(200000):
    ix = torch.randint(0, X.shape[0], (32,))
    emb = C[X[ix]]
    h = torch.tanh(emb.view(-1, 30) @ W1 + b1)
    logits = h @ W2 + b2
    loss = F.cross_entropy(logits, Y[ix])
    for p in parameters: p.grad = None
    loss.backward()
    lr = 0.1 if i < 100000 else 0.01   # decay
    for p in parameters: p.data += -lr * p.grad

Minibatches make each step ~1000× cheaper. The gradient is noisier, but "it is better to take many approximate steps than few exact ones."

LR finding: sweep the learning rate across a range and watch the loss to locate a good value, then decay it late in training.

train 80% · dev 10% · test 10%

Three-way split: train the parameters on the training set, tune hyper-parameters (hidden size, embedding dim, LR) on the dev/validation set, and touch the test set only once, at the very end.

Part 5

Making It Train Well

Initialisation, activations, gradients & BatchNorm

The "Hockey Stick" Loss

# A confidently WRONG net at init has huge logits
logits = h @ W2 + b2          # values like +13, -9, ...
# softmax is then nearly one-hot on the wrong class
# → loss starts at ~27 instead of ~3.3

# Fix: shrink the output layer at init
W2 = torch.randn((200, 27)) * 0.01
b2 = torch.zeros(27)          # logits ≈ 0 → uniform-ish

Expected loss at init should be roughly -log(1/27) ≈ 3.30 — a model that admits it knows nothing. Big random logits make it scream a wrong answer instead.

# tanh saturation kills gradients
h = torch.tanh(emb @ W1 + b1)
# if pre-activations are large, h is all ±1
# tanh'(±1) ≈ 0  → no gradient flows back

# Fix: scale W1 so pre-activations stay small
# kaiming-ish init keeps each layer's
# activation std ≈ 1
W1 = torch.randn((30, 200)) * (5/3) / 30**0.5

A histogram of h packed at ±1 means dead neurons. Proper scaling keeps activations in tanh's linear region so gradients survive.

The "hockey stick": a badly-initialised net wastes its first hundreds of steps just squashing absurd initial logits down to sane values, producing a sharp early drop then a plateau. Good init removes that wasted phase — the loss starts low and the whole curve improves.

Kaiming-ish Scaling

std(W) = gain / √fan_in   (gain = 5/3 for tanh) 
# PyTorch's built-in does the same thing
torch.nn.init.kaiming_normal_(W1, mode='fan_in', nonlinearity='tanh')

Why divide by √fan_in? Summing fan_in independent products inflates the variance of the pre-activation by a factor of fan_in. Dividing the weights' std by √fan_in exactly cancels it, so activations keep unit variance layer after layer instead of exploding or vanishing.

The gain corrects for the squashing each non-linearity applies — 5/3 for tanh, √2 for ReLU.

BatchNorm — Normalise the Pre-Activations

# Standardise the hidden pre-activations across the batch,
# then let the net learn its own scale (gain) and shift (bias)
hpreact = embcat @ W1 + b1
hpreact = bngain * (hpreact - hpreact.mean(0, keepdim=True)) \
                 / hpreact.std(0, keepdim=True)  + bnbias
h = torch.tanh(hpreact)

Why it helps: by forcing each batch's pre-activations to be roughly unit-Gaussian, BatchNorm makes the network far less sensitive to exactly how the weights were initialised — the "hockey stick" tuning above becomes much less fiddly. It also adds a mild regularising noise, since each example's normalisation depends on the rest of its batch.

BatchNorm — Train vs Eval Running Stats

# Buffers updated during training (NOT trained by backprop)
bnmean_running = torch.zeros((1, 200))
bnstd_running  = torch.ones((1, 200))

with torch.no_grad():                       # exponential moving average
    bnmean_running = 0.999*bnmean_running + 0.001*hpreact.mean(0, keepdim=True)
    bnstd_running  = 0.999*bnstd_running  + 0.001*hpreact.std(0, keepdim=True)

# At eval / sampling time there may be no batch — use the running stats
hpreact = bngain * (hpreact - bnmean_running) / bnstd_running + bnbias

The catch with BatchNorm: at training time each example is normalised using its batch's statistics, which is fine. But to score or sample a single name there is no batch. The fix is to keep an exponential moving average of the mean and std during training and use those fixed "running" stats at eval time — the train/eval behaviour now differs, a subtlety you must get right.

Part 6

Going Deeper: WaveNet

Fuse the context hierarchically, not all at once

Flat Concat vs Hierarchical Fusion

The idea (DeepMind's WaveNet, 2016): rather than crushing the whole context into the hidden layer in one step, fuse two characters at a time, then fuse those results, and so on — a tree. Each layer combines a little more context, giving the network a deeper, more expressive view of longer sequences.

FlattenConsecutive — the Key Operation

class FlattenConsecutive:
    """ Group every `n` consecutive elements along time into the channel dim. """
    def __init__(self, n):
        self.n = n
    def __call__(self, x):
        B, T, C = x.shape
        x = x.view(B, T // self.n, C * self.n)   # fuse n neighbours
        if x.shape[1] == 1:
            x = x.squeeze(1)                      # drop a spurious dim
        self.out = x
        return self.out
    def parameters(self):
        return []

This replaces the single big flatten. Where the MLP did emb.view(-1, block_size*n_embd) once, FlattenConsecutive(2) merges only neighbouring pairs, halving the time dimension each layer. Stacking several of them builds the hierarchical tree above.

A torch.nn-like API, Built by Hand

class Linear:
    def __init__(self, fan_in, fan_out, bias=True):
        self.weight = torch.randn((fan_in, fan_out)) / fan_in**0.5  # kaiming
        self.bias = torch.zeros(fan_out) if bias else None
    def __call__(self, x):
        self.out = x @ self.weight
        if self.bias is not None: self.out += self.bias
        return self.out
    def parameters(self):
        return [self.weight] + ([] if self.bias is None else [self.bias])

# The model is just a Sequential stack of these hand-made modules
model = Sequential([
    Embedding(vocab_size, n_embd),
    FlattenConsecutive(2), Linear(n_embd*2, n_hidden, bias=False), BatchNorm1d(n_hidden), Tanh(),
    FlattenConsecutive(2), Linear(n_hidden*2, n_hidden, bias=False), BatchNorm1d(n_hidden), Tanh(),
    FlattenConsecutive(2), Linear(n_hidden*2, n_hidden, bias=False), BatchNorm1d(n_hidden), Tanh(),
    Linear(n_hidden, vocab_size),
])

Re-implementing Linear, BatchNorm1d, Tanh, Embedding and Sequential from scratch demystifies torch.nn — each is a tiny class with a __call__ and a parameters() method. The training loop stays identical to Part 4. This is exactly how PyTorch's own modules are structured.

Key Takeaways

1

Counting and a neural net agree. A bigram count matrix and a one-layer net trained by gradient descent reach the same loss — the net is just a more general, scalable way of writing the same idea.

2

Context is capacity. Widening from one previous character (bigram) to several (MLP) and then fusing them hierarchically (WaveNet) steadily lowers the loss and yields more name-like samples.

3

Getting training right matters as much as the architecture. Initialisation, activation statistics, and BatchNorm decide whether a net learns at all — the unglamorous details are the difference.
